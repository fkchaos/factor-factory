# ADR-0001 · 六层解耦架构 + 插件式 Factor 接口 + 接口层防前视

- **状态**：Accepted ｜ **日期**：2026-08-04 ｜ **作者**：量化因子生产线（主理人）

## 背景（Context）

用户要求框架"充分考虑可扩展 / 可解耦 / 可测试"。同时历史评估（见工作区 `a-share-quant-sim-评估报告`）表明，前视偏差是个人量化系统最致命、也最隐蔽的失效来源（疑似导致 +935% 虚高收益）。需要一套架构，让好因子能被持续、可验证地生产，坏因子在进门之前被挡掉。

外部调研（RESEARCH_LOG R2026-0804-01 Qlib）确认：松耦合、因子以"可调用接口"声明、数据层内建 point-in-time，是成熟方案。

## 决策（Decision）

1. **六层解耦**：data / factors / engine / validate / portfolio / monitor，层间只依赖 Protocol/ABC 接口，核心逻辑禁止 import 具体实现。
2. **插件式 Factor**：统一定义 `Factor.compute(panel, as_of_date, ctx) -> pd.Series`，因子注册到 `registry`；新增因子 = 新文件 + 注册，零改核心引擎。
3. **前视防护在接口层强制**：引擎传给 `Factor.compute` 的 `panel` 必须只含 `as_of_date` 及之前数据；因子实现不得自行取全样本。`as_of_date` 是契约参数，不是可选提示。
4. **PIT 对齐归 DataProvider 责任**：财报披露滞后由数据层按"公告日期 ≤ 交易日期"过滤，而非依赖数据源原生能力（Tushare 不原生提供 PIT）。
5. **成本显式可配置**：`CostModel` 作为独立接口，禁止引擎内部写死成本假设。

## 选项考量（Options Considered）

- **A. 单文件脚本式（如原 a-share-quant-sim 的 v27→v73 文件复制）**：开发快，但不可解耦、难测试、版本爆炸、前视靠自觉 → 否决。
- **B. 全功能 ML 平台（照搬 Qlib）**：能力全，但引入模型库复杂度，超出"因子工厂"定位 → 部分采纳其解耦与 PIT 思想，不引入模型层。
- **C. 六层解耦 + 插件式 Factor（采纳）**：扩展性/可测试性最佳，前视可在接口层阻断，符合用户三项硬要求。

## 影响（Consequences）

- 正面：新因子/数据源/成本模型均零改核心；前视在架构层被强制；测试可针对接口独立 mock。
- 负面：初期脚手架工作量大于单文件脚本；需维护接口契约稳定性（接口变更要走新 ADR）。
- 风险：接口设计若过早固化可能限制表达力 → 通过 Phase 1 先用经典 6 类因子跑通验证接口够用，再扩展。
