## 一、复盘核心摘要（原文要点）

v75a→v75f 系列（科技趋势增强策略）的完整历程：

| 版本 | 改动 | WF Sharpe | 结论 |
|------|------|-----------|------|
| v75a | 突破+放量+流动性 三因子 | 1.642 | ✅ |
| v75f | +广度过滤 | **1.806** | ✅ 最优 |
| v75h | 因子权重优化 | 1.612 | ❌ 全量↑ 但 WF↓ = 拟合噪声 |
| v75i | 因子参数优化 | 1.680 | ❌ 同上 |

**关键发现（原文）**：
1. 三因子全局 IC：突破 -0.014 / 放量 -0.011（弱信号）、流动性 -0.054（唯一有效）
2. **分 regime 后：突破/放量在"强势"（广度 50-75%）下 IC 转正**（+0.009/+0.012）→ regime-dependent alpha
3. **广度过滤的真正作用不是风险控制，而是 regime 选择器**——让策略只在因子有效的状态下交易
4. v75h/v75i 优化弱信号 = 拟合噪声（全量回测 Sharpe ↑ 但 WF Sharpe ↓）
5. A 股技术因子半衰期 ~18 个月，衰减真实存在（流动性 IC 2021 年 -0.066 → 2025 年 -0.026）

**根本教训**：**regime 选择（什么时候交易）比因子选择（选什么股票）更重要。**

## 二、对照审查：我们已防住 / 盲区 / 可借鉴

### ✅ 已防住（我们工厂已有对应机制）

| 复盘教训 | 我们的对应机制 | 状态 |
|---------|--------------|------|

| 因子衰减真实存在 | monitor/monthly_review.py 已做 IC 衰减检测（decay 标记） | ✅ 但只有全局，未量化半衰期（见盲区） |

| 工程：DEBUG 抑制 | （长期任务已后台化 + 日志文件） | ✅ 部分 |

### ⚠️ 盲区（复盘揭示我们也没做）

1. **分 regime 的 IC 分析——我们完全没有**
   - 我们的 validator / monthly_review / universe_matrix 全是**全局 IC**，没有任何按市场状态（牛/熊/震荡、广度高低、波动率区间）分组的 IC 分析。
   - 复盘证明：**全局 IC 有误导性**——突破因子全局 -0.014 看着没用，但强势状态下 +0.009 是 alpha；流动性全局 -0.054 有效，但分状态看其实是"小票溢价"在不同状态下的表达。
   - 后果：我们用全局 IC 可能**误杀 regime-dependent 因子**（看到 IC<0.03 就判弱信号），或**误判因子的真实机制**。

2. **因子半衰期未量化**
   - monthly_review 只有"本月 IC vs 全期 IC 对比 + decay 标记"，没有滚动 IC 窗口（如 3 个月）和半衰期估算。
   - 复盘给的量级参考：A 股技术因子半衰期 ~18 个月（AI 时代更快）。

3. **时序信号（regime/择时/市场情绪）在产品线里没有位置**（详见第三节，这是本审查最重要的结论）

### 🔧 可借鉴（可直接落地的改进）

1. **validator 加"分状态 IC"维度**：按市场状态（建议先用简单代理：指数相对 MA 趋势 / 市场广度百分位 / 波动率分位）分组算 IC，输出到因子卡片 + 月度评审。门槛低，复用现有面板即可。
2. **monthly_review 加滚动 IC 半衰期**：3 个月滚动 IC 窗口 + 线性衰减率估算，量化"这因子还能用多久"。
3. **弱信号禁止优化写进红线**：IC<0.03 的因子权重/参数优化一律不做（v75h/v75i 的直接教训）——我们 f0003a 组合方法决策时也适用（弱信号下 ICIR 加权 = 拟合噪声，等权更稳）。

## 三、核心问题回答：regime / 择时 / 情绪判断，与其他因子"一视同仁"吗？

**结论先行：流程纪律一视同仁；检验指标、交付物形态、消费方式必须不同。**
**更准确地说：regime / 择时 / 市场级情绪本质是"时序信号"，不是"横截面选股因子"。我们现在的流水线是横截面因子专用——时序信号硬塞进来会被误杀（IC≈0 判死刑），这不是它们没用，是用了错误的尺子。**

### 3.1 两类东西的本质区别

| 维度 | 横截面因子（我们现有流水线） | 时序信号（regime/择时/市场情绪） |
|------|---------------------------|-------------------------------|
| 输出 | 每股一个分数（打分排序） | 一个市场/组合级的状态判断（该不该交易、加仓还是减仓） |
| 检验指标 | RankIC / ICIR / 分层回测 / 多空组合 | 方向命中率、状态识别准确率、叠加后的组合 Sharpe/回撤改善 |
| 过拟合风险点 | 参数/权重优化、多因子组合 | **regime 事后划分（用未来信息定状态）、状态样本少** |
| 交付物 | f-code 包：card + 因子值面板 + correlation + backtest + overfit_audit | 状态定义文档 + 状态序列 + 各状态下的绩效统计 + 稳定性指标（切换频率/驻留时长） |
| 消费方式 | 选股模型打分 | 组合层 overlay（仓位开关 / 风险预算） |

### 3.2 "情绪判断"是特例，要拆成两半

- **个股级情绪**（龙虎榜资金流、融资余额变化率、个股换手拥挤度）→ 每股有值 = **横截面因子**，走现有流水线完全没问题，一视同仁成立。
- **市场级情绪**（涨跌停家数、两市成交额、恐贪指数）→ 市场一个值 = **时序信号**，是择时层的东西，不走因子流水线。

### 3.3 对我们工厂的现实影响（现状判断）

- 现有链条 factors/ → validate/ → portfolio/ → monitor/ **全部为横截面选股因子设计**。
- 灵感池漏斗的假设模板（"X 高 → 未来 N 日收益高/低"）天然是横截面表述；时序信号假设（"当状态 S 出现 → 组合应减仓"）写进去后，**没有对应的检验链可以接**。
- 因此只有两个出路（待用户拍板）：
  - **A. 新建"时序信号产品线"**：regime overlay 独立于因子流水线，复用 f-code 编号体系但交付规格不同（状态文档+绩效统计，不是因子值面板）。中后期价值大（复盘证明 regime 选择是真 alpha）。
  - **B. 明确挡在因子链外**：regime/择时留在策略层内部做（像 v75f 广度过滤那样），因子工厂只做横截面因子，但 validator 补"分状态 IC"能力，让横截面因子也能识别自身在哪些状态下有效。

### 3.4 对复盘发现的一点补充思考

复盘结论"regime 选择比因子选择更重要"在我们语境下要说得更精确：**不是因子不重要，而是"因子的有效性高度依赖市场状态"——把"因子在什么状态下有效"这件事研究清楚，本身就是横截面因子研究的上层能力。** 所以两条路不互斥：B 路补的分状态 IC，是 A 路（regime 产品线）的地基。
