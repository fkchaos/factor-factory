# 因子研发科普与生产线总览

> 本文档是给"想搞懂量化因子研究到底在干嘛"的人看的。
> 前半部分用大白话讲**原理和故事**（科普），后半部分讲**我们实际怎么干**（生产线导览）。
> 不要求任何金融/编程背景，照着读就行。

---

## 0. 一句话梗概

量化研究员一辈子只干一件事：**找更多"给股票打分"的靠谱规则，或者把已有的规则改得更稳**。
我们这个项目（factor-factory）就是把"找规则 → 验证规则 → 交付规则"做成一条**工厂流水线**，
让想法能持续地变成可以交给下游策略研究员使用的因子包。

---

## 1. 因子到底是什么（先把这个搞懂）

别被"因子"俩字吓到。说白了：

> **因子就是一个给股票打分的规则。**
> 输入一堆数据 → 输出一个分数 → 分数高的股票，未来更可能涨（或跌，看你做多还是做空）。

我们用代码写了几个现成的因子，感受一下：

| 因子名 | 打分逻辑（大白话） | 赌什么 |
|--------|-------------------|--------|
| `SizeFactor` 规模 | 公司越小打分越高 | 赌小盘股长期更猛 |
| `MomentumFactor` 动量 | 过去 20 天涨得多的打分高 | 赌涨势会延续 |
| `ReversalFactor` 反转 | 过去 5 天涨太多的打分低 | 赌短期涨多了会回调 |
| `ivol` 特质波动率 | 波动越异常的打分越高 | 赌被错杀的会修复 |
| `隔夜跳空` | 今开比昨收高的打分高 | 赌隔夜信息驱动延续 |

这些"打分规则"就是因子。你每天听到的"动量因子""价值因子""质量因子"，全是这个意思。

---

## 2. 一个因子的完整生命周期

从"一个点子"到"能交付的因子包"，要走这么一圈（这就是我们的主线）：

```
点子萌芽
  → 假设定调（这个因子逻辑上凭啥有效？）
  → 因子构造（标准化 + 行业/市值中性化 + 前视防护防作弊）
  → 双重检验（IC 回测 + DSR/PBO 过拟合审计）
  → 交付成 f-code 包（带说明文档）
  → 月度监控（发现衰减就触发回环改造）
       ↺ 回到"假设定调"重做
```

- **假设定调**：先把"我赌的是什么、凭什么"写清楚，再动手。
- **因子构造**：把原始打分变成干净、可比、不会被自己作弊污染的信号。
- **双重检验**：确认这个信号真的有用，而且不是运气。
- **交付**：打包成下游能直接用的东西（见第 10 节）。
- **监控 + 回环**：用一阵子发现不灵了，就回去改，而不是扔掉重来。

## 3. 点子从哪来：四条源头

最顶上的"点子萌芽"来自这四个地方：

1. **学术论文（最主流、最干净）**
   金融顶刊每年发几百篇"我发现了一个能预测收益的现象"。研究员照着复现成一个因子。
   我们 `zoo_basics.py` 的动量、反转、规模，全是 1990 年代论文里的经典发现，到现在还在用。
   好处：逻辑已经被同行审过，可信度高。

2. **盘感规则化（实战派）**
   基金经理炒了十几年，感觉"每逢节前容易跌""早上开盘半小时能预示全天"。
   这些盘感写成代码，就变成因子。我们 `overnight_intraday`（把隔夜和日内收益拆开看）就有这味道——
   老手知道隔夜和盘中是两种完全不同的资金逻辑。

3. **数据挖掘（最危险）**
   直接拿几百个指标和收益率做统计扫描，"诶这个组合预测力最强"。
   这条路**很容易造出假规律**（过拟合），所以我们框架专门加了 DSR/PBO 两道审计来防它。
   学术界管这叫"p-hacking"，挖出来的因子十有八九样本外就废了。

4. **经济逻辑推导（最硬核）**
   从"市场为什么该这样"倒推。比如"风险高的资产理应给更高回报"→ 波动大的该涨更多 → 做波动率因子。
   逻辑最站得住，但不一定短期有效。

> **我们的取向**：偏向 **1 + 2**（学术经典 + 实战盘感），数据挖掘只当辅助验证，绝不拿它当主源头。

## 4. 学术界是怎么"发现"规律的（三道闸）

你可能会问：论文里"我发现了一个能预测收益的现象"，他是怎么发现的？
答案是——**和业界同源**，学者的火花也是从上面四条路（盘感/数据/逻辑）蹦出来的，
只是学者把它们套进了一套更严的"程序"。学术多出"三道闸"：

1. **排除替代解释**：我发现"小公司收益高"，但审稿人会问：是因为风险更高？流动性更差？还是定价效率低？
   必须把这些控制掉，确认"超额收益"不是别的原因的副产品。
2. **跨市场 / 样本外复现**：美国有效，那日本、欧洲、A股呢？换个时间段呢？不能只挑好看的样本说事。
3. **同行评审**：发表前几个同行想方设法挑你漏洞，筛掉一大批"看着美但经不起扒"的规律。

> 这三道闸，正好对应我们项目里的 **DSR/PBO 过拟合审计 + 月度评审**——我们把学术的"三道闸"工程化了。

几个经典因子的真实出身（都挺朴素）：
- **规模效应（Banz, 1981）**：本来研究"上市门槛是不是让小公司被忽视"，结果意外发现小盘股收益系统性更高。
- **动量（Jegadeesh-Titman, 1993）**：当时"有效市场理论"称王，他俩偏要挑衅：检验"过去半年赢家，未来半年还赢不赢"。结果赢家继续赢。
- **价值股（Fama-French, 1992）**：大规模扫变量时，意外冒出来"便宜股长期跑赢贵股"。

**共性**：学者最初的观察基本来自三种姿势——读文献发现漏洞、对主流理论故意唱反调、对市场现象单纯好奇。
这些全归到第 3 节的源头 1~4 里。

## 5. 什么契机会让你推倒重做一个因子

因子不是做完就一成不变。触发"回去改"的契机就这几种：

1. **IC 衰减（最常见）**：IC = 我的打分和股票未来实际涨跌的相关度。做完时 IC 挺好，
   跑半年变低甚至变负——说明规律被套利掉了，或市场结构变了。**月度评审干的就是盯这个。**
2. **过拟合审计没过**：交付前跑 DSR/PBO，发现纯属运气。要么砍掉，要么回炉重造。
3. **逻辑被证伪**：原来以为"小盘永远有效"，结果政策一变、流动性收紧，小盘集体崩，前提没了。
4. **跟别的因子撞车**：新因子和已有高度相关（比如又做了个"近 1 月涨幅"，跟动量 0.9 相关）。
   一般不推翻，而是**做正交化**——剔掉重叠部分只留增量，或合成组合因子。
5. **数据/频率升级**：原来只有日频，后来有分钟级，把粗糙因子重做得更精细。

## 6. 我们的三条腿走路策略

因子来源不是只有"拿现成成果验证"。我们明确是**三条腿**：

- **腿 1 · 继承验证（拿现成成果做二次验证 + 改造）**
  论文/研报里的因子，我们拿来适配 A 股、加中性化、换频率。
  不只是验证对不对，还包括"继承后改造"（如经典动量拿到 A 股要调）。
  → 对应 `zoo_basics`、已落地的 `overnight_intraday`、`ivol`。

- **腿 2 · 原创假设（我们自己产出点子）**
  靠观察力、盘感、跨市场对照提出新假设。这条最吃"人"，但**盘感是可训练的肌肉**（见第 7 节）。
  → 对应 `microstructure.py`（从 A 股涨跌停/T+1 机制推导）。

- **腿 3 · 系统挖掘（用方法和机器扩大产出）**
  不靠拍脑袋，靠体系和工具产出新因子。详见第 8 节。
  → 对应 `feature_factory.py`（特征工厂，ML 挖掘的地基）、`build_combo.py`（组合创新）。

**论坛野路子归哪条腿？** 不算新腿，并入**腿 1 的漏斗**（见下）。

## 7. 论坛野路子怎么纳入（漏斗化，不破闸门）

论文和论坛逛两天就没新东西了。我们希望**持续产生或抓住新的想法火花**，
于是把论坛也纳入，但绝不直接当结论，而是当成"待验证假设"丢进和我们自己提的假设**完全相同的检验流程**。

做法（`scripts/idea_backlog.py` 实现）：
- 任何来源（论文/研报/论坛/自己拍脑袋）的点子先入库变成"待验证假设"。
- **写不出可证伪假设的，直接留在池子里不进流程**（论坛噪声大多死在这关）。
- 能写出来的，和论文源走完全相同的 IC / DSR/PBO / 月度监控闸门。
- 论坛源进来 `confidence_seed=low`（默认置信度低），但假设写得清楚一样过闸门。

**意义**：不是"采纳论坛结论"，而是"扩大假设候选池"。漏斗严，论坛就是免费的高质量灵感；漏斗松，就是垃圾进场。

### 原创假设能力怎么练（反馈闭环）

盘感不是玄学，是可训练的肌肉：
1. **海量看数据**，培养"不对劲"的直觉（异常一眼瞥出）。
2. **跨市场对照**：A 股规律美股成立吗？成立→可能是普遍人性（靠谱）；只在 A 股→可能是本地噪声（谨慎）。
3. **读文献故意挑刺**：拿经典因子当靶子，问"它哪里可能失效"，练"假设生成肌肉"。
4. **写因子日记 / 灵感池做反馈闭环**：每个异象写下来标"我觉得这能成"，**3 个月后回看哪些真有效**——只有"写下预测→时间验证"的闭环能校准自我美化的盘感。
5. **和实战派聊天**：基金经理的盘感是结构化数据的盲区。

> 工程化载体：灵感池 + 上面的反馈闭环。我们观察→入库→检验→3 个月后统计自己的"假设命中率"。
> 别人的盘感停在脑子里，我们的盘感能进池子、被检验、被复盘。

## 8. 第三条腿：系统挖掘的可行性与门槛

我们把系统挖掘拆成四种方式，按"可行性 × 价值"排了落地顺序（见 `docs/PLAN_THIRD_LEG.md`）：

| 方式 | 价值 | 门槛 | 我们状态 |
|------|------|------|---------|
| **组合/正交创新** | 中高 | 最低 | ✅ 已在做（`build_combo.py` / `f0003a`） |
| **微观结构推导**（A股特色：涨跌停/T+1/集合竞价） | 中高 | 低 | ✅ 已落地（`microstructure.py`） |
| **纪律化 ML 挖掘** | 最高 | 中高 | 🔜 地基就绪（`feature_factory.py`），待接 |
| **另类数据**（卫星/供应链/舆情） | 大 | 最高 | ⏸ 暂放 |

**关于 ML 挖掘的门槛（常见误解澄清）**：
- **不是算力**：因子挖掘是表格任务（股票×日线×价量特征），CPU + sklearn 足够，和"训大模型要几张 A100"两码事。
- **真正的门槛**在四件事：① **特征工厂缺失**（最大门槛，现在特征维度还不够宽）② 过拟合管控升级（Purged CV + Walk-forward）③ 可解释性（SHAP→写进说明文档）④ 多重检验校正（FDR）。
- 结论：**ML 不是做不起，是特征工厂这地基还没铺满**——而 `zoo_basics` + 后续因子就是在累积特征维度，铺好就能接。

## 9. 想法供给怎么持续（侦察兵机制）

论文/论坛是"存量"，逛完就空。我们建了**因子侦察兵（Factor Scout）**当专职"逛街员"：

- 一个后台自动化任务（`automation-1785931876198`），**每周一、周四晚 19:00** 自动扫街。
- 扫四类源：学术论文（SSRN/arXiv）、券商金工研报、因子动物园（AQR 等）、实战论坛。
- 只保留能写成"带方向+持有期"的可证伪假设的灵感，去重后灌入灵感池 CSV。
- 跑完刷新因子看板（`docs/factor_board.html`）。
- 你不用再操心"逛不逛得动"，池子会自己长。

这解决了你最担心的点——**这事能不能持续做下去，关键在想法的持续供给**。
灵感池 + 漏斗把"产生想法"和"验证想法"解耦了，流水线永远有活干，
加上反馈闭环，你的"发现能力"本身也随项目变强。这就是**火花 → 工厂 → 因子 → 策略 → 再火花**的飞轮。

## 11. 工程纪律（为什么我们的"有效"可信）

项目里有几条硬纪律，保证检验出来的"有效"不是自己作弊造出来的：

- **框架分层 + 契约防火墙**（`data/contract.py`）：接口层规定格式/单位，数据源 provider 负责转换，绝不允许不一致（曾踩过 Tushare 复权口径冲突的坑，加了 `assert_adj_policy` 防火墙）。
- **前视防护**（`slice_panel_to_date`）：构造因子时严格只用"当前日期之前"的数据，杜绝未来信息泄漏（这是量化最常见的作弊方式）。
- **过拟合审计**（DSR/PBO）：交付前必过，筛掉纯运气的因子。
- **f-code 编号**（`fNNNNx`）：数字是谱系号、字母是微调版本，所有因子平级、带说明文档，下游可溯源。

## 写在最后

量化因子研究没那么神秘：
- **想法**大多从论文和盘感来，改造大多因为"不灵了"或"被发现是假规律"。
- **我们的体系**把"产生想法 → 验证想法 → 交付因子 → 监控改造"制度化了：
  前者靠灵感池 + 侦察兵（持续供给），后者靠契约防火墙 + 前视防护 + 过拟合审计（质量兜底）。
