## 0. 背景：我们现在的"两条半腿"

- **腿1 · 继承验证**（在做）：论文/研报/论坛点子 → 灵感池漏斗 → 检验闸门 → f-code
- **腿2 · 原创假设**（在做）：观察/盘感 → 灵感池 → 反馈闭环校准 → 检验闸门
- **腿3 · 系统挖掘**（未立，本计划主题）：不依赖"人拍脑袋"或"别人已经发现"，用工程化手段规模化产出候选因子

腿1/腿2 解决"想法从哪来 + 怎么质控"。但两者本质都靠"外部输入或人的灵感"——论文逛完会枯竭，盘感培养有上限。腿3 是让"产生候选因子"这件事本身**可规模化、不依赖单点灵感**。

## 3. 方式B：微观结构推导（A股特色，建议立项）

- **逻辑**：从 A股独有交易机制本身推导因子。美股没有这些机制 → 论文里无现成因子 → 我们有地利。
- **候选因子方向**：
  - 涨跌停因子：涨停封单量 / 跌停板上抛压 / 连板天数 / 炸板率
  - T+1 因子：当日买入不可卖 → 隔夜跳空的信息含量（与现有 `overnight_intraday` 互补）
  - 开盘集合竞价因子：9:15-9:25 虚拟撮合量价变化 / 撤单率

- **优势**：数据源全是日线/分钟线（已有），无额外采购；规则公开确定性高。
- **实现路径**：新建 `factors/microstructure.py`，每个因子走 Factor 协议 + 前视防护 + 中性化，进 validator 链。

## 4. 方式C：纪律化 ML 挖掘（中期，门槛不在算力）

### 4.1 常见误解
**"ML 挖掘门槛在算力" —— 错。** 因子挖掘是表格任务（~1572 只 × 几年日线 × OHLCV+市值+行业），CPU 跑 XGBoost / 线性 / 小神经网络足够。我们 venv 里 numpy/scipy 现成，sklearn 一键装。和"训大模型要 A100"完全两码事。

### 4.2 真正的四个门槛（按难度）

**① 特征工厂缺失（最大门槛）**
ML 挖掘前提是"有几百个候选特征让它挑"。我们当前特征空间太窄（价格/换手率/市值/行业），`zoo_basics` 才 3 个因子。
→ **必须先建特征工厂**：批量产出 cross-sectional 基础特征（各窗口动量/波动/流动性/量价背离/相对强度…）。
→ `zoo_basics` + 后续因子实现，本质就是在累积特征维度。特征够宽，ML 层自然能接。

**② 过拟合管控升级**
ML 自由度极高，现有 DSR/PBO（给因子组合设计，CSCV）不够。
→ 需扩：Purged CV + Embargo（防未来信息泄漏到训练）+ Walk-forward 滚动验证。

**③ 可解释性（交付硬要求）**
交付物给**选股策略研究员（人）**消费。黑箱得分下游难用。
→ 需 SHAP 归因 / 因子载荷解释，把黑箱转成能写进 card.md 的逻辑。

**④ 多重检验校正**
扫几千特征组合，假发现率（FDR，Benjamini-Hochberg）必须上，否则回到 p-hacking 右边路。

### 4.3 落地路线图（依赖顺序）

```
Phase C1（特征工厂）：features/engine.py 批量产出 N 个基础特征（复用 validator 中性化链）
        ↓
Phase C2（ML 筛选）：XGBoost/线性 + Purged CV + Walk-forward，FDR 校正选显著特征组合
        ↓
Phase C3（可解释转换）：SHAP 归因 → 反推成可写 card 的线性因子 → 进 validator 链
        ↓
Phase C4（交付）：走 build_deliverable.py 打 f-code 包（与腿1/腿2 同闸门）
```

- **待办**：
  - [ ] 现有 DSR/PBO 闸门评估能否直接复用（ML 模型 selection 场景），不能则扩 Purged CV
  - [ ] 特征工厂 `features/engine.py` 立项（Phase C1）
